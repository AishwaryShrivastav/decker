# Decker v0.1.4 implementation plan

## 1. Provider foundation

Add typed provider contracts and a registry under
`apps/extension/src/providers/`. Implement OpenAI key validation,
transcription, and text generation with the current models. Implement Gemini
validation, file upload and transcription, and ordinary and streamed text
generation with the current stable models.

Add `apps/extension/src/shared/providerSettings.ts` for the versioned active
provider record and transparent migration from `openaiKey`. Route the
background worker through the selected adapter while retaining the current
OpenAI popup response and save payload. Validate a non-empty key before writing
settings. Add only `https://generativelanguage.googleapis.com/*` beside the
existing OpenAI host permission.

Write focused provider and settings tests before implementation, then update
background tests for migration, validated saves, provider routing, and failed
validation. Run extension tests, TypeScript, and the Chrome build. Commit this
phase separately without changing release copy, UI, version, or ZIPs.

## 2. Popup setup and readiness

Update `apps/extension/src/popup/Popup.tsx` and shared messages so the popup only
shows setup, readiness, and recording. Add provider choice, provider-specific
key help, save-time validation state, eligible-tab readiness, microphone state,
and recording progress. Muted tabs and tabs without recent audio remain eligible
with warnings; captured-track and signal checks decide whether capture works.
Replace the Google Meet hostname gate with checks for an eligible browser tab
and actionable capture errors. State that native apps are unsupported.

Add popup and background tests for both providers, muted tabs, unsupported
browser pages, capture denial, and recovery. Keep the existing consent and
direct-provider disclosures beside the start action.

## 3. Review and artifact page

Create a dedicated extension page under `apps/extension/src/review/`, add it to
the build and manifest resources, and open or focus it when recording stops.
Move transcript editing, topic selection, research status, output choice,
generation progress, copy, and download from the popup to this page. Preserve
the durable session and stale-revision protections.

Add tests for reopening review, worker restart, edited transcript conflicts,
provider-aware generation, and download recovery. Check keyboard navigation,
focus, narrow windows, and long transcripts.

## 4. Public copy and privacy

Update `README.md`, the website pages under `apps/web/app/`, and
`store-assets/listing.md`, `store-assets/privacy.md`,
`store-assets/submission-fields.md`, and `store-assets/requirements.md`.
Remove Claude and Google-Meet-only claims. Describe direct OpenAI or Gemini
processing, validation requests, Gemini's temporary uploaded audio handling,
local settings and recovery data, eligible browser tabs with clear silence or mute warnings, and the native
app limit. Apply the supplied anti-slop guide to every public paragraph.

Update screenshots and promotional assets only where the changed interface is
visible. Build the website and review desktop and mobile layouts.

## 5. Release package

After all implementation and copy are approved, bump the extension and manifest
versions to 0.1.4, update `CHANGELOG.md`, build Chrome, regenerate
`store-assets/decker-chrome.zip`, and update
`scripts/verify-extension.py` for both provider origins and the review page.

Run extension tests, TypeScript, extension builds, website build, ZIP
verification, and manual provider and capture checks. Record the evidence in
the store verification documents. Publishing and pushing remain separate,
explicit release actions.

Decker v0.1.4 is Chrome-only. Do not build or package Firefox until a functional
Firefox capture and recorder path is implemented and tested.
